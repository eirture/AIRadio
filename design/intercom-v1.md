# 灵矽语音对讲第一版设计

状态：设计草案。目标硬件为 Waveshare ESP32-S3 Touch LCD 3.5B；其他板型需单独验证触摸、PSRAM 和音频能力。

## 1. 目标与边界

第一版实现同一广播域内在线设备之间的录音式语音对讲。用户在屏幕上点击“录音”开始采集，再点击“发送”结束采集；完整语音先存于本机 PSRAM，录制结束后经独立 WebSocket 连接发送。服务端将 Opus 帧转发给除发送者外的其他在线设备，接收端播放。

- 配置项只有本机 ID 和对讲服务器地址；地址只接受 `ws://`，不提供 `wss://` 选项。
- 第一版只有一个固定的全局广播域；不填写目标 ID，也不创建或切换房间。
- linxd 继续负责语音助手与 OTA，不承载对讲音频。对讲使用独立连接、消息协议和服务。
- 服务端不提供历史消息或离线补播。调试 WAV 默认保存到本地，可通过启动参数关闭。第一版不做鉴权、群管理、语音切群或跨实例路由。
- 这是“录完再发”，不是按住即实时传声。接收端最快在发送者点击“发送”后开始听到声音。

## 2. 当前代码基础

- 目标板在 `config.h` 中启用了 `TOUCH_ENABLE`，`InitializeTouch()` 已将触摸设备注册到 LVGL。当前板级实现使用 AXS15231B 触摸驱动，实际控制器仍需实机确认。
- BOOT 键单击调用 `Application::ToggleChatState()`；第一版保留该助手操作。
- `AudioService` 已有 16 kHz 单声道、60 ms 一帧的 Opus 编解码任务。其发送和播放队列有容量限制，不能存整段录音。
- Wi-Fi 配网页面由 `78__esp-wifi-connect` 提供，已有“高级设置”页签和 `/advanced/config`、`/advanced/submit` 接口。固件的 `Settings` 可读写 NVS；对讲配置加入现有页面，不复用 linxd 的 `websocket` 设置。

## 3. 用户流程与界面

### 配网页面中的对讲设置

设备进入 Wi-Fi 配网模式后，用户连接设备热点并打开 `http://192.168.4.1`，在现有“高级设置”页签配置对讲。不新增页面、HTTP 端口或 STA 模式下常驻的配置服务。

| 字段 | 规则 |
| --- | --- |
| 本机 ID | 启用时必填，1～32 位 ASCII 字母、数字、`-`、`_`；在线 ID 必须唯一。 |
| 对讲服务器地址 | 启用时必填，完整 `ws://host:port/path` URL；拒绝其他 scheme、空主机、过长输入和用户信息。 |

页面通过 `/advanced/config` 回填字段，随其他高级设置提交到 `/advanced/submit`。设备端再次校验，保存到独立 NVS 命名空间 `intercom` 下的 `device_id`、`server_url`。保存失败必须返回错误。两项都为空表示停用；只填一项时提示补全，不能覆盖上一次有效配置。Wi-Fi 信息仍按原流程保存。

不修改 `board.uuid`、OTA 地址或 linxd WebSocket 配置。退出配网模式并连接 Wi-Fi 后配置生效；后续每次启动从 NVS 读取并连接服务。连接状态显示在设备屏幕上。第一版仅在可信环境部署。

配网实现来自托管组件，项目规则禁止直接修改 `managed_components/`。扩展应保存在项目维护的源码覆盖目录中；升级组件时检查兼容性。

### 设备触摸操作

在目标板主界面底部放置尺寸稳定的对讲控件，保留聊天内容和状态栏。LVGL 回调只把动作交给应用任务，不能在回调中采集、编码、等待网络或阻塞播放。

| 当前状态 | 控件动作 | 结果 |
| --- | --- | --- |
| 未配置、断线、助手忙、正在播放 | 禁用 | 显示简短原因，不开始录音。 |
| 就绪 | 点击“录音” | 开始录制；控件变为“发送”，显示录音时长。 |
| 录制中 | 点击“发送” | 停止采集，完成最后一帧编码后上传。 |
| 发送中 | 禁用 | 显示发送状态，结束或失败后恢复。 |

录制中可取消并丢弃缓冲，不联网发送。达到时长或容量上限时自动结束并尝试发送已完成帧，界面给出提示。屏幕休眠后第一次触摸应只唤醒，不误触录音或发送。录制和接收播放使用不同状态提示，不能叠加两路声音。

### 助手与对讲的关系

第一版采用音频互斥：只在助手 `Idle` 且没有其他播放时允许录音或接收播放；录制、发送、播放期间不让助手抢占音频。收到语音但设备忙时直接回复 `busy`，不长期堆积。对讲状态由应用任务协调；主设备状态仍经 `Application::SetDeviceState()` 和状态机修改。唤醒检测、输入和播放恢复时机需实机验证。

## 4. 固件模块与数据流

应用自有的对讲管理模块负责读取配置、连接维护、录音会话、有界 PSRAM 缓冲、协议收发和 UI 状态。目标板显示层只呈现控件及上报动作；网络层不依赖具体板类；音频通过 `AudioService` 的窄接口接入，不直接从板级代码操作 codec，也不占用助手的发送队列。

```text
点击录音 -> 应用任务申请音频 -> 麦克风 -> Opus 编码 -> 有界 PSRAM 会话缓冲
点击发送 -> 停止采集并完成最后一帧编码 -> WebSocket 逐帧发送
服务端 -> 其他在线连接 -> 接收端解码队列 -> 扬声器
```

缓冲保存每帧的长度和字节，不保存 PCM，也不把整段录音拼成单条 WebSocket 消息。显式分配 PSRAM 并检查失败，为屏幕、摄像头、AFE 等任务预留空间，不能假定标称 8 MB 全部可用。

首版上限为 **30 秒**和 **512 KiB** 编码音频，先达到任一限制即停止；60 ms 一帧最多 500 帧。编码队列必须有背压或显式丢帧统计。编码跟不上、分配失败或 Wi-Fi 断开时应停止会话，不能悄悄发送残缺录音。上传期间保留本机缓冲，直到服务端确认完整接收或上传失败后释放。

Wi-Fi 连通且配置有效后建立 WebSocket；断线采用有上限的指数退避重连。网络回调只验证并投递工作，不在回调里播放音频、写 NVS 或等待队列。上传和接收播放任务分离；按每帧 60 ms 的语音时长发送，避免灌满接收端小队列。接收端只保留短缓冲，并在本段结束后排空播放队列。

## 5. 第一版 WebSocket 协议

每台设备只开一条对讲连接，先注册本机 ID。**文本消息为 JSON 控制帧，每条二进制消息恰好承载一个原始 Opus 包**，不是 Ogg 文件或 PCM。控制帧和音频帧在同一条有序 WebSocket 连接上发送。

示例流程：

```text
设备 -> 服务端  {"type":"hello","version":1,"device_id":"truck-01"}
服务端 -> 设备  {"type":"hello_ack","ok":true}
发送端 -> 服务端  {"type":"start","message_id":"...","frame_ms":60,"sample_rate":16000}
服务端 -> 接收端  {"type":"start","source_id":"truck-01","message_id":"...","frame_ms":60,"sample_rate":16000}
接收端 -> 服务端  {"type":"receive_ready","message_id":"..."}
服务端 -> 发送端  {"type":"start_ack","message_id":"...","ok":true}
发送端 -> 服务端  Binary: 第 0 帧原始 Opus 包
发送端 -> 服务端  Binary: 第 1 帧原始 Opus 包
发送端 -> 服务端  {"type":"end","message_id":"...","frame_count":2}
服务端 -> 发送端  {"type":"end_ack","message_id":"...","ok":true}
```

每段录音的 `message_id` 必须唯一，可由随机设备会话标识和递增计数构成。设备在收到 `hello_ack` 后才能发送；一条连接同时最多进行一段语音。`source_id` 由服务端从已注册连接填入，不采信客户端声明的来源。

接收端收到 `start` 后回复 `receive_ready` 或 `busy`。服务端只向限时内回复就绪的设备转发；超时和忙碌设备均跳过。发送端收到 `start_ack.ok=true` 才能发二进制帧，收到 `ok=false` 则停止上传。

一条连接最多只有一段进行中的语音，接收方可按二进制帧顺序计数，并用 `end.frame_count` 核对完整性。重连后旧会话作废，不跨连接续传。单帧上限 4 KiB，整段最多 500 帧、512 KiB。未知类型、缺字段、超大帧、未注册发送、超限或乱序 `start/end` 应报错并丢弃当前会话，必要时关闭连接。连接保活使用 WebSocket ping/pong。

`end_ack.ok=true` 仅表示服务端完整接收，**不保证每个接收者成功播放**。第一版不重传、不保证必达、不补播离线消息。仅一台设备在线时也允许注册和发送：服务端不向发送者回放，返回 `end_ack.ok=true`、`receivers=0`，不会因没有接收者报错。

## 6. 转发服务

服务端维护 `device_id -> WebSocket 连接` 映射，拒绝重复 ID 的新连接，不悄悄顶下线。所有已注册设备属于同一个固定广播域。收到 `start` 后检查资源上限及全局发言占用，再向除源设备外的在线连接发送开始消息。

同时只允许一段全局广播语音；其他发送端收到 `busy`。每个接收连接有有界发送队列和写超时，慢连接或断线设备被跳过，不能拖慢其他设备。转发路径只保留少量在途帧。开启调试 WAV 后，服务端逐帧解码并写入本地临时文件，完整 `end` 后保留，中断则删除。发送者异常断线时向已收到 `start` 的接收者发送 `abort`。

接收端核对 `message_id`、`frame_count` 和结束标记，不能把中断片段当作完整消息。首版使用单实例服务；横向扩展需另行设计跨实例路由。

## 7. 失败与资源规则

- 未配置或服务不可达：显示“对讲未连接”并禁用录音；助手照常运行。
- 录制中 Wi-Fi 断开：停止并丢弃本段，不保留离线待发消息。
- 上传时断线或被拒绝：提示失败并释放缓冲，不自动重发，避免重复播放。
- 接收时设备忙：拒绝本段，不无限追加到 `AudioService` 解码队列。
- 达到录制时长或内存上限：结束并尝试发送已完成帧，显示上限提示。
- 服务端限制连接数、二进制帧和控制帧大小、会话时长及写入等待时间。

第一版只使用明文 `ws://`，没有设备鉴权。同链路的其他参与者可能读取或伪造音频与 ID；只能用于可信内网。公网或正式车队使用前需另行解决认证和传输保护。

## 8. 实施顺序与验收

1. 在配网页面高级设置中增加两个字段，完成校验、NVS 持久化和设备连接状态；确认重启后仍有效且不影响 linxd。
2. 加入触摸控件与音频互斥，先验证本机录制、发送、取消、超时和分配失败，BOOT 键保留助手功能。
3. 接入 Opus 会话缓冲和 WebSocket 协议，用两台目标板与一个转发进程验证广播播放。
4. 验证页面回填、保存失败提示、退出配网后生效、Wi-Fi 重连、重复 ID、慢接收端、同时发送、助手忙、屏幕唤醒、30 秒录制及连续发送。

验收时应确认 A 向 B 完整发送而 A 不回放；加入第三台后 B、C 均能播放；B 离线期间没有历史补播；同时发送不混音；异常路径不出现无界队列、重复播放、卡死或重启。记录从点击发送到接收端出声的延迟、PSRAM 峰值和丢帧数。成功编译不能代替实机触摸、麦克风、扬声器和网络验证。

## 9. 本地运行与调试

1. 准备一台运行服务的电脑，以及一台或两台 Waveshare ESP32-S3 Touch LCD 3.5B，接入同一个可信局域网。电脑安装 Go 1.24+、CGO 编译器和 `libopus` 开发包；macOS 运行 `brew install opus`，Debian/Ubuntu 运行 `sudo apt install libopus-dev pkg-config`。固件尽量使用 ESP-IDF `release/v6.1`，最低支持 v6.0.1。
2. 在仓库根目录加载 ESP-IDF 环境，编译指定板型并为每台设备刷机：

   ```sh
   source /path/to/esp-idf/export.sh
   python3 scripts/build.py waveshare/esp32-s3-touch-lcd-3.5b --name esp32-s3-touch-lcd-3.5b
   idf.py -p /dev/ttyUSB0 flash monitor
   ```

   把串口替换为本机实际名称。构建脚本会修改本地 `sdkconfig` 和构建状态，刷机前确认选中的仍是该板型。
3. 在另一个终端启动 Go 服务。`0.0.0.0` 允许局域网连接；设备配置应填写电脑的局域网 IP，不能填写 `0.0.0.0` 或 `127.0.0.1`。

   ```sh
   cd server
   go run . -listen 0.0.0.0:8080
   ```

   默认把完整上传保存为 `server/recordings/` 中的 16 kHz 单声道 WAV。可用 `-record-dir /path/to/recordings` 改目录，或用 `-save-wav=false` 关闭。启动日志显示保存目录，录制完成后打印文件路径。WAV 含真实语音，不会自动清理。
4. 设备进入现有 Wi-Fi 配网模式，连接其热点并打开 `http://192.168.4.1`。在“高级设置”填写唯一的本机 ID（例如 `truck-01`）和 `ws://<电脑局域网IP>:8080/ws`，保存后完成 Wi-Fi 配网并退出配网模式。联网后设备应显示“录音”；若显示“对讲未连接”，检查地址、电脑防火墙和局域网连通性。两项均留空表示停用对讲。
5. 单设备也可点击“录音”再点击“发送”：服务端应接受上传，日志中 `receivers=0`，开启保存时生成 WAV，发送设备自己不会回放。接入另一台不同 ID 的设备后，从 A 发送并确认 B 播放、A 不回放。录制中按 X 取消，不生成完整 WAV。

调试 WAV 只是服务器本地排查文件，不会发给离线设备，也不作为正式业务录音。编译成功和单设备试跑不能代替两台实机的触摸、音频与断线验证。

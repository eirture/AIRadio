# 小智对讲客户端界面设计（480×320 横屏）

状态：界面方案，待固件实现。

## 1. 设计目标

客户端主要通过小智语音和 MCP 操作房间，不在屏幕上提供复杂的房间管理菜单。触摸屏只保留一个核心动作：按下大按钮开始对讲，松开结束对讲。

界面需要同时表达：

- 设备运行状态。
- 当前对讲状态和活动房间。
- 小智聊天记录。
- 未来的对讲音频与文字记录。

目标屏幕按横屏 `480×320` 设计。部分固件配置以竖向 `320×480` 定义，实际旋转后按横屏布局使用。

## 2. 总体布局

采用左侧控制区、右侧聊天记录区的两栏布局：

```text
┌────────────────────────────────────────────────┐
│ 设备状态                  │       聊天记录       │
│ Wi-Fi ●  电量 82%         │                    │
│ 当前房间：城东车队         │  小智：已加入城东车队  │
│ 对讲状态：空闲             │                    │
│                            │                    │
│        ┌──────────┐        │                    │
│        │          │        │                    │
│        │  对讲按钮 │        │                    │
│        │          │        │                    │
│        └──────────┘        │                    │
│                            │                    │
│  对讲状态：已连接           │                    │
└────────────────────────────────────────────────┘
```

建议左侧占约 38%（约 180 px），右侧占约 62%（约 300 px），中间使用 1 px 分割线。左侧区域需要保留足够宽度，避免状态文字和按钮拥挤。

## 3. 左侧控制区

### 3.1 设备状态

顶部显示设备基础运行信息：

- Wi-Fi 连接状态。
- 电量或供电状态（硬件支持时显示）。
- 小智服务连接状态。
- 必要时显示“未配置”“连接中”“已连接”“已断开”。

示例：

```text
设备状态
Wi-Fi ●   电量 82%
小智：已连接
```

### 3.2 对讲状态

显示当前设备的活动房间和对讲连接状态：

```text
对讲状态
房间：城东车队
状态：已连接 · 3 台在线
```

房间创建、加入、退出、切换和邀请接受由小智通过 MCP 完成。MCP 调用成功或失败后，左侧状态更新，右侧聊天记录显示自然语言反馈。

### 3.3 大对讲按钮

这是界面唯一主要触摸操作，建议放在左侧中部：

- 圆形或大圆角按钮。
- 直径约 120～140 px，或宽 145 px、高 80 px。
- 默认显示“按住说话”。
- 按下后开始采集，松开后结束并发送。
- 按下时显示“正在说话”和持续时间。
- 发送完成后恢复“按住说话”。
- 达到服务端时长或帧数限制时自动结束并提示。

状态示例：

```text
空闲：       [ 🎙 按住说话 ]
录音：       [ ● 正在说话 03s ]
发送中：     [ ↑ 正在发送 ]
远端播放：   [ ▮▮ 设备 004 正在说话 ]
```

建议颜色：

- 正常空闲：深绿色。
- 正在录音：红色或橙色。
- 远端播放：蓝色。
- 断开或错误：灰色或红色。

设备忙、未配置或未连接时按钮禁用，并在按钮下方显示简短原因。

## 4. 右侧聊天记录区

右侧作为小智聊天记录的主要显示区域，保留现有助手对话体验。房间操作不通过触摸菜单完成，而是在这里显示语音指令和结果：

```text
用户：加入城东车队
小智：已加入城东车队
```

建议按时间从上到下排列，最新内容靠近底部。内容超出区域后滚动，保留有限数量，避免占用无界内存。

未来对讲记录可以混合显示在同一时间流中，但使用颜色或标签区分来源：

```text
09:42  小智
      已加入城东车队

09:43  设备 004
      [音频] 请在东门集合

09:44  我
      [音频] 收到
```

来源颜色建议：

- 小智消息：深绿色。
- 本机对讲：蓝色。
- 远端设备对讲：橙色。
- 系统错误：红色。

## 5. 语音和 MCP 操作

房间相关操作主要由语音触发：

```text
用户：加入城东车队
小智：找到“城东车队”，正在申请加入
设备：调用 join_room MCP
小智：已加入城东车队
```

```text
用户：创建一个临时调度群
设备：调用 create_room MCP
小智：房间已创建，当前房间是临时调度群
```

屏幕只反映执行结果，不增加房间列表、加入码输入框或复杂设置页。收到房间邀请时，聊天记录显示邀请内容，设备通过语音确认接受或忽略。

## 6. 状态转换

| 状态 | 左侧显示 | 按钮行为 |
|---|---|---|
| 未配置 | 对讲未配置 | 禁用 |
| 连接中 | 正在连接 | 禁用 |
| 已连接空闲 | 当前房间、在线数量 | 可按住开始 |
| 正在录音 | 正在说话、计时 | 松开结束 |
| 正在发送 | 正在发送 | 禁用，等待完成 |
| 远端播放 | 设备 ID 正在说话 | 可按住发言，按音频策略互斥 |
| 已断开 | 对讲未连接 | 禁用 |
| 失败 | 简短错误原因 | 根据状态恢复或禁用 |

收到 `room_state` 时更新当前房间；收到 `room_invite` 时作为聊天/通知事件显示，不自动切换房间。

## 7. 后续扩展

第一版固定保留右侧聊天记录区域的空间，即使暂时没有完整音频历史，也显示“暂无对讲记录”。后续可以逐步加入：

- 音频播放按钮和波形。
- 对讲语音转写文字。
- 发送者设备 ID和时间。
- 播放、发送、接收失败状态。
- 房间邀请和系统事件。

实现时继续遵守音频互斥、有限队列和应用任务调度要求；LVGL 触摸回调只提交开始/结束动作，不能执行网络、编码或阻塞播放。
